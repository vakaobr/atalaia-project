# Tools

Developer scripts.

| Tool | What it does |
| --- | --- |
| [`check.sh`](check.sh) | Checks the generated protocol files, the project page and the formatting, builds the core and runs its tests, the simulator's tests, every game mode's tests, the field controller's tests (with the C host modem, the C host box and Mosquitto) and the site server's tests that need no database: the same checks as CI, apart from the firmware jobs, the console's browser tests, the site server on PostgreSQL (`docker_server.py`) and the app's Dart tests and Android builds (`docker_app.py`); it builds the FFI stub so that the simulator's ctypes structs are checked against it |
| [`format.sh`](format.sh) | Formats the core's C (clang-format 18) and the modes' Lua (StyLua); `--check` fails if anything needs formatting, as CI does |
| [`protogen.py`](protogen.py) | Generates the C and Python protocol tables, the C test vectors and the JSON Schema from `protocol/schema/`; `--check` fails if they are stale. See [protocol/README.md](../protocol/README.md#changing-the-schema) |
| [`pairing_vectors.py`](pairing_vectors.py) | Writes `protocol/vectors/pairing.json` ([protocol/adoption.md](../protocol/adoption.md) section 7): draft-irtf-cfrg-cpace-14's Appendix B.1 and B.1.10 vectors, copied from the draft and checked against `atalaia_sim.cpace` first, a whole pairing run with fixed values and the frames to refuse; `--check` (in `check.sh`) fails if the file is stale. Needs the cryptography package |
| [`field_frame_vectors.py`](field_frame_vectors.py) | Writes `protocol/vectors/field_frame.json` ([protocol/field-frames.md](../protocol/field-frames.md)): RFC 5869's HKDF cases, checked against the cryptography library first, and sealed field frames with fixed nonces; `--check` (in `check.sh`) fails if the file is stale. Needs the cryptography package |
| [`atak_xml_vectors.py`](atak_xml_vectors.py) | Writes `protocol/vectors/atak_xml.json`: the Pi controller's ATAK emitter's answers (`controller/atalaia_controller/atak.py`: escaped and capped texts, times, colours, whole CoT events and map features), which the Android field controller's port checks byte for byte (PE24 slice S7); `--check` (in `check.sh` and CI) fails if the file is stale. Needs Python 3.12 |
| [`gen_mode_gifs.py`](gen_mode_gifs.py), [`mode_gifs.yaml`](mode_gifs.yaml) | Makes the modes page's animated pictures (`site/img/modes/*.gif`, with a still of each) from the firmware's own screen code: the scripts in `mode_gifs.yaml` (the screens each mode shows as a game goes on) are drawn on the Field Box's TFT and OLED by the host program `firmware/esp32/test/mode_gif_frames.c` (built and run in Docker, or with `--frames-exe` where it is already built), framed in the box's body and written as small GIFs by a plain-Python encoder, so the same code always gives the same bytes: `python3 tools/gen_mode_gifs.py` writes them, `--check` fails if a file is not what the code draws (CI's firmware-test job), `--only <id> --lang <code>` makes some, `--list` shows the sizes. Adding a mode is one entry in the YAML; see [site/README.md](../site/README.md#game-mode-animations) |
| [`build_site.py`](build_site.py) | Builds the project site, every page of its page table (`PAGES`: the main page, modes, radio, roadmap and glossary) in Portuguese (`site/`, the default) and English (`site/en/`), the radio diagrams (`site/img/diagrams/`) and `site/sitemap.xml`, from the templates and partials in `site/src/` and the texts in `site/i18n/`; `--check` fails if a page, diagram or the sitemap is stale, a translation is missing a key, has an unused one or does not fit its diagram, a link, image or `#id` on any page leads nowhere, a page is missing in a language, or a generated file no longer has a source. See [site/README.md](../site/README.md#translating-the-pages) |
| [`render_diagrams.py`](render_diagrams.py) | Draws the seven architecture diagrams of `docs/architecture.md` as plain SVG for the project page, in every language: fills the Mermaid templates `site/src/diagrams/arch-*.mmd` from `site/i18n/*.yaml` and runs the Mermaid CLI in Docker (`minlag/mermaid-cli`), with CSS variables for the site's light and dark colours and a fingerprint in each SVG that `build_site.py --check` verifies (CI cannot run Mermaid). `--force` draws all again, `--png DIR` writes PNGs to look at. See [site/README.md](../site/README.md#architecture-diagrams-mermaid) |
| [`docker_sim.py`](docker_sim.py) | Runs any simulator command (`serve`, `test`) in the dev container, from any shell: `python tools/docker_sim.py serve modes/bomb` |
| [`prepare_release.py`](prepare_release.py) | Prepares a release the way commit 331dcaad did by hand (`.github/workflows/prepare-release.yml`): `prepare` moves CHANGELOG's Unreleased section under the next version and bumps `version.h`, CMake, the app, the controller and the server; `open-dev` sets the next development version after the tag; `check` and `notes`. Standard library only; "Cutting a release" in [CONTRIBUTING.md](../CONTRIBUTING.md) |
| [`release_package.py`](release_package.py) | Packages a firmware build for a GitHub release (`.github/workflows/release.yml`): the USB flash bundle (`-usb.zip`), the merged image for browser flashers (`-merged.bin`), the app image, and the release notes from the CHANGELOG; signing is `firmware_release.py`'s, `docs/manuals/en/firmware.md` |
| [`docker_fw.py`](docker_fw.py) | Builds the ESP32 firmware (`build`), its Wokwi emulator variant (`wokwi`), the USB radio modem variant (`modem`), the I/O pod variant (`pod`), the bench variant for a bare board on the desk (`bench`) and runs its host tests (`test`, `test --update-screens`) in Docker, from any shell; every image's version carries the commit it was built from (`0.3.0-dev.164+g8560d54`, worked out on the host; `version` prints it, decisions FV-1 to FV-4); the Field Box builds take `--fw-version=` (an exact version) and `--release-keys=` (firmware updates). See [firmware/esp32/README.md](../firmware/esp32/README.md#build) |
| [`docker_server.py`](docker_server.py) | The site server in Docker, as CI's `server` job: `test [names]` runs its tests and `migrations` the Alembic round trip (upgrade head, downgrade base, upgrade head, `alembic check`) in its test image next to an ephemeral `postgres:16-alpine` (Docker Compose, `server/docker-compose.test.yml`), removed afterwards; `build` builds the server image; `up` starts a local trial of the deployment behind Caddy on `https://localhost:8443` (Caddy's own certificate; `ATALAIA_HTTPS_PORT`, `ATALAIA_HTTP_PORT`; a random database password and secret key; `python -m atalaia_server create-admin` in it makes an administrator) and `down` stops it and deletes its database; `deploy` is the deployment test, as CI's `server-deploy` job (`server_deploy.py`: `server/setup.sh`, the stack behind Caddy, HTTPS and the WebSocket through it, `backup.sh`, and `restore.sh` into a fresh database with every table compared; the remote ATAK relay's published port and a device enrolled with `atak issue`); `deploy-hosted` is the hosted hub's, as CI's `server-deploy-hosted` job (`server_deploy_hosted.py`: `setup.sh --hosted`, two fields behind Caddy's on-demand TLS and its `ask` endpoint, the isolation as the server's role, `backup.sh` and `restore.sh` into a fresh hub with ownership, grants and row-level security compared; each field's ATAK device getting only its own field's events). See [server/README.md](../server/README.md#tests) |
| [`docker_editor.py`](docker_editor.py) | Runs the mode editor's browser tests (headless Chromium; the generator's unit tests and the round trip of the example projects through the hand-written modes' tests) in Docker, in the console's test image: `python tools/docker_editor.py` (`-k NAME` for some). See [simulator/README.md](../simulator/README.md#write-a-mode-in-blocks) |
| [`docker_console.py`](docker_console.py) | Runs the GM console's browser tests (headless Chromium against the real controller) in Docker, from any shell: `python tools/docker_console.py` (`-k NAME` for some). See [controller/console/README.md](../controller/console/README.md#tests) |
| [`docker_app.py`](docker_app.py) | The app's whole pipeline in Docker, as CI's `flutter-test`, `core-android-ndk` and `flutter-build-android` jobs: `python tools/docker_app.py` runs all three; `check` builds the core, the FFI stub and the host pod, modem and box (the box with mbedtls linked statically, so it runs in the Flutter image) in `atalaia-dev`, then runs `flutter analyze`, the `dart format` check and `flutter test` (the bridge, the game loop isolate and every mode's tests on the real core) in the pinned Flutter image (`ghcr.io/cirruslabs/flutter:3.44.0`); `test [paths]`; `ndk` cross-compiles the core for three Android ABIs; `apk` runs `flutter build apk --debug`; `format`, `lock`. Not part of `check.sh`: the dev container has no Dart. See [app/README.md](../app/README.md#tests) |
| [`bench_radio_log.py`](bench_radio_log.py) | Reads the boxes' `radio_stats` log lines (a log file or a live port, opened without raising DTR/RTS) and prints a per-minute table, a summary (retries per event, % acked, the duty budget's slope, refusals) and the relay study's row for the field size: `python tools/bench_radio_log.py box.log --boxes 5` (decision SL-18, [runbook](../docs/runbooks/radio-field-test.md)) |
| [`bench_lbt_gate.py`](bench_lbt_gate.py) | The listen-before-talk bench gate's report (decision SL-25, [runbook](../docs/runbooks/lbt-bench-gate.md)): reads the prober board's serial log (`LBT,` lines from `@lbt probe` on a bench image), rebuilds every received frame's window on the air, prints the hit rate by tenth of the frame, by part and by what saw it, the false-busy rate and the measured CAD time against SL-25's 4 ms, and PASS (above 90 % in every tenth) or FAIL; `--capture COM3 --send "@lbt probe 300"` types the command and saves the log; a log from `@lbt probe 100 proxy=as923` (AS923-TW's modulation on 868.3 MHz, SL-25's detPeak 23 test) is reported with its profile, CAD settings and duty limit, and refused (exit 66) outside 868.0-868.6 MHz or on 920-925 MHz; `--selftest` checks the tool (in `check.sh` and CI) |
| [`serial_bridge.py`](serial_bridge.py) | Serves a serial port on TCP for a field controller in Docker that cannot see COM ports: `python tools/serial_bridge.py COM3 7001`, then `socket://host.docker.internal:7001` in `[adopt] usb_ports` (USB adoption, [protocol/adoption.md](../protocol/adoption.md)) or `[modem] port` (with `--baud 921600`); opens the port without raising DTR or RTS. Needs only pyserial |
| [`registry_page.py`](registry_page.py) | The community registry's public page, built from its `index.json` and `registry/template/site/page.yaml` (English, `pt/`, `de/`, `zh-tw/`; every registry-supplied string escaped); `registry_check.py site` calls it |

| [`firmware_release.py`](firmware_release.py) | Release keys and signed firmware releases for the Field Box's updates over the air: `keygen` (an Ed25519 key, encrypted, refused inside the repository), `pubkey`, `sign IMAGE --key KEY` (checks the image's own descriptors, writes `IMAGE.release.json`), `verify`; the manifest is the shared `controller/atalaia_controller/firmware_release.py`. See [firmware/esp32/docs/RELEASE_SIGNING.md](../firmware/esp32/docs/RELEASE_SIGNING.md) |
| [`breached_hashes.py`](breached_hashes.py) | Builds the site server's breached-password file as hashes (decision S11-4) from the pinned SecLists list, downloaded or `--source FILE`, checked by its SHA-256 |

Using the dev container (from the repository root):

```sh
docker build -t atalaia-dev tools/dev
docker run --rm -v "$PWD:/src" atalaia-dev sh tools/check.sh
```

On Windows, use `${PWD}` in PowerShell or `$(pwd -W)` in Git Bash for the volume path.

`docker_sim.py`, `docker_fw.py`, `docker_console.py`, `docker_editor.py` and `docker_app.py` keep their build caches in named Docker volumes (for `docker_app.py`: the Dart packages, the core built for the tests, the Android NDK and CMake, and Gradle's downloads); `docker_server.py` names its Compose projects and images `atalaia-server-test`, `atalaia-server-trial` and `atalaia-server`. To run them from two checkouts at once (for example a git worktree), give each its own volumes, projects and images with `ATALAIA_VOLUME_SUFFIX`, e.g. `ATALAIA_VOLUME_SUFFIX=-p3 python tools/docker_fw.py test`.
