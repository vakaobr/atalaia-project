# The scenario compiler

The validator and the compiler of custom scenarios (ADR-P4-6 as amended, decisions M7-1 to M7-9, PE24-109): a GM's manifest in, its problems and its `kind: scenario` package (`mode.yaml` and `field.lua`) out. It is written once, in Lua, and runs inside the C core ([`../include/atalaia/scenario.h`](../include/atalaia/scenario.h)), so the Pi's controller (through ctypes, [`controller/atalaia_controller/scenarios/`](../../controller/atalaia_controller/scenarios/)) and the phone's (through `dart:ffi`, [`app/lib/controller/scenarios/`](../../app/lib/controller/scenarios/)) give the same problems and the same package byte for byte. Until 2026-10-23 there were two implementations, Python on the Pi and a Dart port on the phone, kept alike only by the shared vectors (decision PE24-84); the rules now change in one place.

What stays per controller is reading the manifest's text: the Pi with PyYAML, the phone with its PyYAML-compatible reader (YAML 1.1: `yes` is true, `0815` a text, `1:30` a number, merge keys, a key given twice refused, a surrogate pair's escapes joined, PE24-107, an impossible date refused, PE24-108). Both are checked against the `loads` of [`protocol/vectors/scenario_compile.json`](../../protocol/vectors/scenario_compile.json).

| File | What it is |
| --- | --- |
| `main.lua` | The entry points: `check`, `compile` and `literal` |
| `tree.lua` | The manifest's data tree (below) read into Lua, and the answer's JSON |
| `py.lua` | The values a reader builds, with the Python semantics the rules were written with: equality (`1 == 1.0 == True`), truth, `str()` and `repr()` for the problems' paths and messages, a float's shortest `repr`, `json.dumps`'s length |
| `unicode.lua` | Printable, control and white-space characters, generated by [`tools/scenario_unicode.py`](../../tools/scenario_unicode.py) from Python's `unicodedata` (15.0.0) |
| `manifest.lua` | The names, limits and objective types |
| `validator.lua` | Every rule: each problem with its path, code, message and level |
| `luagen.lua` | `field.lua`: the `SCENARIO` table, every value a Lua literal (decision M7-3), then the runtime |
| `yaml.lua` | `mode.yaml` as PyYAML's `safe_dump(sort_keys=False, allow_unicode=True, width=100)` writes it: block maps and lists, PyYAML's choice of plain, single- or double-quoted texts and its folding at 100 columns, `&id001` anchors |
| `package.lua` | `mode.yaml`'s content |
| `protocol.lua` | The radio size of a scenario event, from the core's protocol tables |
| `runtime.lua` | The scenario runtime: the code after `SCENARIO` in every compiled `field.lua` (GPL-3.0-or-later, decision M7-2) |

Two optional top-level keys shape a squad's chain (decisions SQ-1 to SQ-10): `reveal: all | active` (with `active`, an objective that depends on others and gives no `visibility` is compiled as `hidden`, so the runtime reveals it when it opens) and `disclosure: members | leader` (copied to `mode.yaml`'s `scenario` block when given; the controllers route by it, nothing in `field.lua` changes).

The build turns these files into a C file ([`../cmake/embed_scenario.cmake`](../cmake/embed_scenario.cmake)); `ATALAIA_SCENARIO=OFF` leaves the compiler out, and the Field Box's firmware never builds it. Each call runs in a Lua state of its own, with the base, string, table, math and utf8 libraries and no way to load other code, a memory limit (64 MB) and an instruction limit (200 million; the largest manifest that compiles takes about 4 MB and 14 million). A manifest past either limit is a problem, `too_complex` (decision PE24-113). The manifest is only ever data: no text of it becomes code, here or in `field.lua`.

## The data tree

A controller hands the core what its reader read as JSON in UTF-8, every value typed, as the `loads` of `scenario_compile.json` write them, so that `1`, `1.0`, `true` and `"1"` stay apart:

| JSON | The value |
| --- | --- |
| `{"str": "text"}` | a text |
| `{"int": "-12"}` | an integer of any size (past 64 bits it stays exact) |
| `{"float": "1e-05"}` | a float, as Python's `repr` writes it (`nan`, `inf`, `-inf` too) |
| `{"bool": true}`, `{"null": null}` | a boolean, None |
| `{"timestamp": "2026-10-23 10:00:00+01:00"}` | a YAML date or date and time, as Python's `str()` writes it |
| `{"list": [values]}` | a list |
| `{"map": [[key, value], ...]}` | a map, in its order; any value may be a key |
| `{"alias": n}` | the n-th list or map again (0 is the first one begun, in the text's order): a YAML alias, or one object in two places. A list may hold itself; a map two objectives share is written once in `mode.yaml`, with an anchor, as PyYAML does |
| `{"other": {"repr": "{1, 2}", "truthy": true}}` | a value of a kind no rule takes (a set or bytes, which PyYAML's `!!set` and `!!binary` build): only its `repr` and its truth matter |

A `\u` escape is one code point and is never joined with the next one: half of a surrogate pair (in a map built in code, never in a manifest read from text) stays half, and the validator says where (`bad_unicode`). A tree nested more than 100 levels deep is a problem, `bad_manifest`. A text that is not a data tree is `{"error": "..."}`, the caller's bug.

## The answer

```json
{"ok": true, "problems": [{"path": "nodes.spare", "code": "unused_node", "message": "no objective targets this node", "level": "warning"}],
 "id": "org.club.ridge", "version": "1", "files": {"mode.yaml": "...", "field.lua": "..."}}
```

`check` gives `ok` and `problems`; `compile` gives the package too when there is no error; `literal` gives a value as a Lua literal (`{"ok": true, "lua": "..."}`, for tests). The problems are protocol/vectors/scenario.json's: their paths, codes and levels are what programs match, and their messages are the ones the Pi first gave.

## Changing a rule

Change the Lua here, add the case to `protocol/vectors/scenario.json` (the rule) or to `tools/scenario_compile_vectors.py` (a package's text), run `python3 tools/scenario_compile_vectors.py`, and both controllers' tests check it. `core/tests/test_scenario.c` checks the C entry points, the event sizes against the core's codec, the limits and malformed and mutated trees (also under ASan and UBSan).
