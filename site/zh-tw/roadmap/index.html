  3. 軟體已完成

    2 · 場地網路

    LoRa 上的 Skirmesh-RF、場地控制器、API、GM 控制台和一組模式，已在軟體中測試；在工作台上，真實開發板透過無線電和控制器玩完整場遊戲，工作台上發現的問題已在軟體中修正。正在等場地上 5 個組裝好的盒子。

    已完成的部分

    • 加密的 Skirmesh-RF 無線電協定，以及 USB 無線電數據機。
    • 附 API 的場地控制器。
    • 主辦控制台，附記分板。
    • 用 NFC 卡或 QR code 加入遊戲。
    • 盒子韌體和控制器之間的通訊。
    • 一組模式：全佔點（同時守住所有盒子才得分）、最後一人（只剩三個據點之一時開始落敗倒數）、炸彈模式中各隊自己的啟動密碼，以及密碼附加規則（按鍵密碼可以給分、給提示或解鎖，並告訴 GM 是誰用的）。
    • 以上都已在模擬器、仿真器和電腦上測試過，包括整場遊戲；在工作台上，真實開發板透過無線電和控制器玩完整場遊戲：邀請、佔領、以代碼配對、無線更新、取得缺少的模式。
    • 盒子先聽再說：每個盒子發送前先確認頻道空閒，減少訊息碰撞。在模擬器中，20 個盒子的場地收到 89 % 的更新，原本是 65 %。
    • GM 在全佔點中也可以設定或釋放盒子的擁有者，和其他模式一樣。
    • 控制器可以把自己的無線電訊框一個一個、隔開時間送出。已經做好，在場地測試決定之前先關閉。
    • 無線電拒絕韌體更新的提議時，Pi 控制器會立刻讓更新失敗。
    • 設定好的盒子可以回到 Wi-Fi 設定：從需要管理員 PIN 的選單項目，或 USB 主控台的指令。設定頁有英文、葡萄牙文、德文和繁體中文，手機會自己開啟它。
    • 控制台的「遊戲」分頁會顯示給玩家的記分板 QR code。
    • 情境可以用德文和繁體中文撰寫，目標名稱也包括在內。
    • 破壞（Sabotage），新的模式：炸彈一回合接一回合，直到遊戲時間結束。進攻方啟動，防守方拆除；爆炸為進攻方得一分，拆除為防守方得一分，之後盒子休息，下一回合開始。得分較多的隊伍獲勝，同分為平手。已在模擬器和測試中，也在 Field Box 的預設遊戲裡；還沒在真正的開發板上試過。
    • USB 無線電數據機的小螢幕說葡萄牙文、英文、德文和繁體中文，和盒子一樣。僅主機測試，還沒在真正的開發板上試過。
    • GM 控制台的表單會保留主辦輸入的內容直到儲存：玩家報到或控制台的時鐘不再把已儲存的值放回去。
    • 更換場地頻道不再讓空閒的盒子失聯：控制器會告訴它們它去了哪裡（一種新的加密無線電訊息 MOVE，在舊頻道上說三次），「尋找盒子」可以掃過最近四個頻道，找出錯過的盒子。這是在工作台上發現的：一次無線電掃描移動了頻道，閒置的盒子就什麼也聽不到了。已在兩種控制器、模擬器和盒子的程式碼中完成；兩塊開發板上的檢查還沒做。
    • 開始、暫停或繼續大約一秒內就會送到盒子，而不是最多 30 秒：控制器會在 1、2.5、5 和 10 秒後把狀態當作 TIME 訊息再送一次（在工作台上，有個盒子晚了 21 秒才知道遊戲開始）。兩塊開發板上的檢查還沒做。在無線電佔用時間模型中，重送、MOVE 和一次掃描，讓控制器在典型的一小時內於預設子頻段多佔用約 2 秒。
    • GM 控制台會說明更換頻道對空閒盒子做了什麼（三次 MOVE 已說了幾次，然後是控制器已經移動），設定頁有「尋找盒子」按鈕，顯示一次掃描的結果。在占空比低於 10 % 的子頻段，每小時的掃描次數有上限（子頻段預算的 5 %），被拒絕時以及下一次何時可行，控制台都會說明。僅軟體，兩種控制器都有。
    • 預測分數會跟著佔領走：盒子的兩則 STATE 訊息之間，控制器會繼續為佔領事件所指的隊伍計分，直到盒子的下一則 STATE。在工作台上，佔領後緊接著遺失一則 STATE 時預測會出錯；有了這項變更，同樣的工作台設定通過了，盒子的扣分也在工作台上檢查過。
    • 盒子的遊戲結束會結束遊戲：在控制器上沒有場地邏輯的模式（破壞的時間限制、炸彈），遊戲中任一盒子送出的第一個 game.end 就會結束遊戲，以該盒子指定的勝方或平手收場。在炸彈 / Rush 中，爆炸現在會結束遊戲，由啟動炸彈的隊伍獲勝；拆除則不會。這是在工作台上用破壞模式發現的，炸彈的爆炸也在那裡檢查過。
    • 被錄下來的無線電指令不能再於日後重放：每個接收端（盒子、USB 無線電模組和兩種控制器）都為每個發送端保留一個重放視窗，盒子會拒絕比它最後套用的更舊的開始、暫停、繼續、結束或 TIME。遺失了世代（epoch）紀錄的盒子會抽一個新的世代，而不是重複使用 nonce。空中傳輸的格式沒有改變：舊盒子繼續可用，但在更新之前仍然暴露。已在模擬器和電腦上測試，C、Python 和 Dart 共用同一組測試向量；還沒在真實開發板上試過無線電重放。
    • 安全審查帶來的場地控制器強化：限制請求大小；開啟 HTTPS 時，GM 和玩家的權杖在一般 HTTP 上被拒絕（控制台在 https://<控制器>:8443/console/ 開啟）；場地的 MQTT 走 TLS（8883 埠；Pi 上未加密的 1883 只在本機回送位址）；工作人員 ATAK 串流使用 TLS；HSTS；Pi 上強化過的服務單元；經簽署模式的撤銷採失敗即封閉（清單遺失或無法讀取時不安裝任何東西；離線的控制器沿用最後一份清單 30 天）。已在電腦上測試，還沒在場地上的真實 Pi 或手機上試過。
    • 遺失紀元（epoch）儲存、因此以隨機高紀元回來的盒子，現在找得回來：收不開 HELLO 或 TIME 的接收端會搜尋紀元範圍的其餘部分（每次搜尋一段，在既有額度內），聽到這種盒子的控制器則用新的 CMD 訊息把它的紀元告訴其他裝置，這個訊息只能調高紀元。沒有紀錄而繼續的遊戲，控制器的紀元也從隨機值開始，所以 nonce 不會重複。舊盒子會忽略新訊息。在模擬器與電腦上測試，尚未在真實電路板上試過。
    • 第二次遺失紀元儲存時，不會再抽到更低的紀元：盒子、Pi 和手機控制器會在每把金鑰的紀錄之外，另外記住自己用過的最高紀元，抽取從它之上開始；已在某場遊戲中發射過的控制器，不會再以舊節點編號被重新邀請（它會拿到新的編號）；Wi-Fi 道具現在也會收到指出控制器紀元的 CMD 訊息，並轉給它的 I/O 模組（兩種控制器都是）。RFC 0001 修訂 25。在模擬器與電腦上測試，尚未在真實電路板上試過。
    • 模式的 rand() 現在除了遊戲種子與節點編號，還由遊戲金鑰設定，所以玩家從 API 看到的內容無法再推算出來（駭客終端的密碼、標靶時窗的隊伍），遊戲種子也不再顯示給玩家和記分板。同一場遊戲重播結果相同，但在此變更前錄下的遊戲會重播出不同的隨機值：不要在遊戲進行中更新盒子。C、Python、Dart 共用測試向量；尚未在電路板上試過。
    • Lua 沙箱補上了記憶體檢查工具審查發現的漏洞：表格函式、協程與長串回呼都會計量，ESP32 的 C 堆疊深度有上限，超出範圍的節點編號或計時器不再繞回。堆疊數值是計算出來的，尚未在電路板上量測。
    • 天線增益成為編譯選項（--antenna-dbi，0 到 20 dBi，預設 2）：裝了較強天線的盒子會把傳導功率降低相同的增益，並向下取整，讓輻射功率維持在子頻段的限制內。僅主機測試。
    • 即時串流的存取代碼不再出現在網址：控制台把它放在標頭，App 放在 Authorization 標頭，控制器與場地伺服器的日誌會把網址中的代碼值遮蔽（舊網址在過渡期內仍可使用）。日誌曾被分享出去的場地，應更換 GM 與唯讀代碼。
    • 沒有玩家編號的隊伍成績，現在兩種控制器也保存 365 天（遊戲紀錄 90 天），GM 可唯讀查看。已在電腦上測試。

    3 · Android 與玩家

    Android 道具、I/O 模組、玩家 App 和需要手機的模式：軟體已完成，包括 iOS（已在 iPhone 上檢查）。場地測試在等真正的手機和 I/O 模組。

    已完成的部分

    • App：給玩家、裁判和 GM 使用，有葡萄牙文和英文，支援 Android 和 iOS（iOS 版已在 iPhone 上通過檢查清單）。
    • Android 手機可以當作盒子，任何模式都能玩並顯示模式自己的畫面，並透過 QR code、NFC 卡或文字加入遊戲。
    • 手機當場地控制器：軟體已完成，正在等真正的手機；它自己執行遊戲和場地的各項服務。
    • I/O 模組：韌體把一塊 Heltec 開發板的按鈕、按鍵、燈、警報器、NFC 讀卡機和 LoRa 無線電借給手機使用。
    • 使用手機和標籤的模式：擊殺確認、復活與命數、玩家報到、醫護包和印鈔廠。
    其餘已完成的部分，依主題分類

    模式與畫面

    • 擊殺確認、復活與命數和玩家報到會讀取玩家經簽署的 NFC 標籤。
    • 醫護包：中彈的玩家掃描自己的標籤並按住按鈕來接受治療，治療次數有限。
    • 印鈔廠：某隊守住工廠時工廠會產生金錢；玩家用自己的標籤收取，再到另一個盒子存入，場地控制器記住每位玩家身上帶了多少。
    • 以 YAML 描述、由 Field Box 和 App 以相同方式繪製的模式畫面。

    玩家與裁判

    • 玩家在場地掃描印出來的海報就能報到（不需要帳號、不需要網路），說明要用哪幾把槍，並看到自己是否已通過測速。
    • 報到測速：能量、各級別的限制、抽查、由裁判簽署的測速值。裁判依照「待測速槍枝」清單作業，他們簽署的測速值會把每把槍標為通過或拒絕；他們也有槍枝登記冊和玩家標籤。
    • 玩家可以在遊戲中分享自己的位置，由控制器決定誰看得到。
    • 自己架設控制器的場地或社團，可以在 App、記分板和海報上顯示自己的標誌、桌布和顏色，並幫自己的隊伍取名字、加隊徽。
    • 檢查報到海報在印出後被更改時，GM 控制台會通知。
