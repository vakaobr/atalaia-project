路線圖

六個階段，每個階段都以一次真實場地測試收尾，也就是它的「關卡」。軟體進度跑在硬體前面：第 1 到 3 階段的軟體已完成（真實開發板已在工作台上玩完整場遊戲，iOS App 已在 iPhone 上通過檢查清單）；第 4、5 階段的軟體已完成。關卡在等組裝好的盒子、場地測試、一台真正的伺服器和專案的登錄庫金鑰。

  1. 已完成

    0 · 基礎

    共用核心、Lua 沙箱、Skirmesh-RF 編解碼器和瀏覽器模擬器。關卡已通過。

    已完成的部分

    • 共用核心，每個平台都執行的遊戲邏輯。
    • Lua 沙箱，遊戲模式的腳本在其中執行。

    關卡：模擬器能用 Lua 腳本執行佔點與炸彈模式。已通過。

    • 場地的標誌顯示在盒子的大螢幕上。軟體已完成，還沒在真正的螢幕上看過。

    下一步，以及在等什麼

    • 在真正的開發板上試設定重送、換場地和標誌。

    關卡：一個盒子跑完一場 2 小時的社團遊戲，中途不必重新啟動。尚未通過，要等到有組裝好的盒子做到。

  3. 軟體已完成

    2 · 場地網路

    LoRa 上的 Skirmesh-RF、場地控制器、API、GM 控制台和一組模式，已在軟體中測試；在工作台上，真實開發板透過無線電和控制器玩完整場遊戲。正在等場地上 5 個組裝好的盒子。

    已完成的部分

    • 加密的 Skirmesh-RF 無線電協定，以及 USB 無線電數據機。
    • 附 API 的場地控制器。
    • 主辦控制台，附記分板。
    • 用 NFC 卡或 QR code 加入遊戲。
    • 盒子韌體和控制器之間的通訊。
    • 一組模式：全佔點（同時守住所有盒子才得分）、最後一人（只剩三個據點之一時開始落敗倒數）、炸彈模式中各隊自己的啟動密碼，以及密碼附加規則（按鍵密碼可以給分、給提示或解鎖，並告訴 GM 是誰用的）。
    • 以上都已在模擬器、仿真器和電腦上測試過，包括整場遊戲；在工作台上，真實開發板透過無線電和控制器玩完整場遊戲：邀請、佔領、以代碼配對、無線更新、取得缺少的模式。
    • 盒子先聽再說：每個盒子發送前先確認頻道空閒，減少訊息碰撞。在模擬器中，20 個盒子的場地收到 89 % 的更新，原本是 65 %。
    • GM 在全佔點中也可以設定或釋放盒子的擁有者，和其他模式一樣。
    • 控制器可以把自己的無線電訊框一個一個、隔開時間送出。已經做好，在場地測試決定之前先關閉。
    • 無線電拒絕韌體更新的提議時，Pi 控制器會立刻讓更新失敗。
    • 設定好的盒子可以回到 Wi-Fi 設定：從需要管理員 PIN 的選單項目，或 USB 主控台的指令。設定頁有英文、葡萄牙文、德文和繁體中文，手機會自己開啟它。
    • 控制台的「遊戲」分頁會顯示給玩家的記分板 QR code。
    • 情境可以用德文和繁體中文撰寫；目前目標名稱仍是葡萄牙文和英文。

    下一步，以及在等什麼

    • 無線電開發板，以及 5 個組裝好的盒子，用來做場地測試。
    • 用 20 個盒子做場地測試，比較開啟和關閉「先聽再說」。
    • 是否開啟控制器的間隔送出，由 20 個盒子的場地測試決定。

    關卡：在 CQB 場地和戶外場地各用 5 個盒子，佔領一次都沒漏掉。尚未通過。

  4. 軟體已完成

    3 · Android 與玩家

    Android 道具、I/O 模組、玩家 App 和需要手機的模式：軟體已完成，包括 iOS（已在 iPhone 上檢查）。場地測試在等真正的手機和 I/O 模組。

    已完成的部分

    • App：給玩家、裁判和 GM 使用，有葡萄牙文和英文，支援 Android 和 iOS（iOS 版已在 iPhone 上通過檢查清單）。
    • Android 手機可以當作盒子，任何模式都能玩並顯示模式自己的畫面，並透過 QR code、NFC 卡或文字加入遊戲。
    • 手機當場地控制器：軟體已完成，正在等真正的手機；它自己執行遊戲和場地的各項服務。
    • I/O 模組：韌體把一塊 Heltec 開發板的按鈕、按鍵、燈、警報器、NFC 讀卡機和 LoRa 無線電借給手機使用。
    • 使用手機和標籤的模式：擊殺確認、復活與命數、玩家報到、醫護包和印鈔廠。
    其餘已完成的部分，依主題分類

    模式與畫面

    • 擊殺確認、復活與命數和玩家報到會讀取玩家經簽署的 NFC 標籤。
    • 醫護包：中彈的玩家掃描自己的標籤並按住按鈕來接受治療，治療次數有限。
    • 印鈔廠：某隊守住工廠時工廠會產生金錢；玩家用自己的標籤收取，再到另一個盒子存入，場地控制器記住每位玩家身上帶了多少。
    • 以 YAML 描述、由 Field Box 和 App 以相同方式繪製的模式畫面。

    玩家與裁判

    • 玩家在場地掃描印出來的海報就能報到（不需要帳號、不需要網路），說明要用哪幾把槍，並看到自己是否已通過測速。
    • 報到測速：能量、各級別的限制、抽查、由裁判簽署的測速值。裁判依照「待測速槍枝」清單作業，他們簽署的測速值會把每把槍標為通過或拒絕；他們也有槍枝登記冊和玩家標籤。
    • 玩家可以在遊戲中分享自己的位置，由控制器決定誰看得到。
    • 自己架設控制器的場地或社團，可以在 App、記分板和海報上顯示自己的標誌、桌布和顏色，並幫自己的隊伍取名字、加隊徽。
    • 檢查報到海報在印出後被更改時，GM 控制台會通知。
    • 裁判和測速畫面說的就是 App 實際做的事，限制清單也已翻譯。
    • App 用 Android Keystore 封存更多機密資料：場地伺服器金鑰、玩家的機密和伺服器登入。
    • 玩家的 NFC 標籤由場地控制器簽署，可從 GM 控制台、手機控制器或裁判的 App 寫入。裁判不必再為此持有場地金鑰。
    • 槍枝標籤：App 顯示、分享或列印每把槍的 QR 貼紙，GM 控制台可為所有已報到的玩家列印。裁判的待測佇列會掃描它們。
    • 室內位置：GM 在平面圖上放置 BLE 信標，聽到信標的 Android 手機會回報自己所在的房間，而不是 GPS。軟體已完成並以模擬測試，還沒用真正的信標試過。iOS 仍只用 GPS。
    • App 可以從記分板的 QR code 跟上一場遊戲，手機控制器以自己的場地 CA 提供 HTTPS 時也可以。軟體已完成，還沒在真正的手機上試過。
    • 玩家選擇自己在哪一個樓層，並看到場地平面圖和他們可以看到的位置。
    • App 中的遊戲歷史：玩家參加過的遊戲，最新的在最前面。
    • App 可用 Google、Microsoft、Apple 或通行金鑰登入，並有帳號畫面。僅限 Android；還沒在真正的手機上、也沒用真正的登入服務試過。
    • 玩家的場地平面圖可以顯示場地的網格和玩家自己所在的格子。
    • 裁判登記複製品時，可以綁定一張 NFC 貼紙。

    Android 道具與 I/O 模組

    • Android 道具透過場地的 Wi-Fi 加入控制器的遊戲，或透過 I/O 模組用無線電加入。
    • I/O 模組的韌體會透過 USB 或藍牙，把一塊 Heltec 開發板的隊伍按鈕、按鍵、燈、警報器、NFC 讀卡機、外殼開關和 LoRa 無線電借給手機使用。
    • App 會自己重新連上遺失連線的 I/O 模組。還沒用真正的 I/O 模組試過。
    • Android 道具像盒子一樣，向自己的控制器取得已簽署的模式包。軟體已完成。

    手機當場地控制器

    • 遊戲引擎：在共用核心上執行模式的 field.lua，附 MQTT broker 和位置過濾器；REST API、即時串流和 MQTT 主題；重新啟動後保留遊戲；加入資料。
    • 在它的 Wi-Fi 上的 Android 道具、以 I/O 模組當作它的無線電、使用玩家權杖的場地報到、「待測速槍枝」清單和玩家位置。用和 Pi 控制器相同的合約測試案例檢查，並在電腦上搭配 I/O 模組和 Field Box 自己的程式碼執行。
    • 它的畫面：App 首頁上的角色、螢幕關閉時仍持續運作、由 App 提供的 GM 控制台，以及以手機上建立的場地 CA 提供 HTTPS。
    • 場地平面圖（每層一張平面圖、它在地圖上的位置、含場地邊界的地圖標記，以及從地圖載入的場地，因此越界警告在這裡也能運作）和無線電頻道，可透過 I/O 模組尋找安靜的頻道。
    • 透過無線電操作盒子：以密封邀請把盒子邀進下一場遊戲；遊戲結束時通知盒子，即使手機重新啟動後沒有遊戲金鑰也可以；用盒子顯示的代碼或手機以 NFC 寫入的場地卡綁定新盒子；在遊戲之間更新韌體（透過 I/O 模組或 Pi 的 USB 無線電數據機，手機的無線電送不出去時會說明原因）。
    • 預設組合、上傳的模式和經簽署的模式套件（會送給缺少它們的盒子）、在手機上編譯的劇本、遊戲中的角色模式套件，以及隊伍名稱和隊徽。
    • Pi 其餘的功能也有：故障轉移（手機和 Pi 可以互為備援控制器）、與場地伺服器同步（有網路時上傳遊戲、紀錄和分數；從那裡取得報名名單、場地品牌和劇本庫）、遠端 GM 和 ATAK 資訊。
    • GM 控制台可在手機上使用：報到和裁判的表格會上下堆疊，頁面不必左右捲動。

    iOS

    • 專案已在儲存庫中，CI 會在 Mac 上建置，也已在 iPhone 上執行過。
    • 2026-10-26 已在 iPhone 上通過裝置上的檢查清單：12 項自動檢查，加上手動檢查：用相機掃描 QR、以場地海報透過 HTTPS 報到、App 開在畫面上時分享位置、出界警告和震動，以及 atalaia:// 連結。

    下一步，以及在等什麼

    • 用真正的手機和 I/O 模組進行的場地測試（計畫階段 G）正在等硬體。到目前為止，App 已在 Android 模擬器和連上工作台控制器的 iPhone 上執行過，I/O 模組的韌體也只以它自己的程式碼在電腦上跑過。
    • 手機當場地控制器，正在等真正的手機。
    • 在 iOS 上，NFC 需要付費的 Apple 帳號；道具和手機當場地控制器仍只支援 Android。
    • iOS 上的室內信標需要一個要在 Mac 上寫的 Swift 外掛。
    • 用真正的手機和 I/O 模組試記分板 QR code、樓層選擇、遊戲歷史和 I/O 模組重新連線。
    • 在真正的手機上、並用真正的登入服務試 App 的登入。

    關卡：一場遊戲混用 ESP32 和 Android 道具，沒有任何問題。

  5. 軟體已完成

    4 · 場地伺服器與進階玩法

    場地伺服器、遊戲排程與報名、自訂劇本、進階模式、ATAK。軟體的每個步驟都已完成；還需要一台真正的伺服器、一次法律審查和硬體上的測試。

    已完成的部分

    • 進階模式：主站與衛星、駭客終端、VIP / 護送，以及標靶時窗的邏輯。
    • 自訂劇本：在場地控制器上的執行環境、YAML 劇本的編譯器、GM 控制台中的編輯器，以及 App 中的任務目標。
    • ATAK 資料：盒子和據點顯示在 ATAK 地圖上，在場地上，以及透過場地伺服器提供給不在場地的工作人員。
    • 場地伺服器：附兩步驟驗證碼的帳號、個人資料權利、控制器同步、測速登記冊、遊戲歷史和劇本庫。
    • 遊戲排程與報名：附公開場地頁面、行事曆資料訂閱和社團檔案。
    • 託管模式：在一台伺服器上服務多個場地，彼此隔離，並附它的部署。
    其餘已完成的部分，依主題分類

    模式

    • 主站與衛星：和主站一起被守住的衛星會提高主站的分數；主站易手會讓衛星恢復中立。
    • 駭客終端：按鍵上的一道謎題，破解後會揭露一組密碼或佔領這台終端。
    • VIP / 護送：一隊護送自己的 VIP 或一支有 GPS 的手機到撤離區；檢查點盒子被守住時會得分；位置資料只留在場地控制器和手機上。
    • 標靶時窗的規則：標靶顯示某隊顏色時打中它，就替那一隊得分。標靶擴充模組還沒做出來。
    • 核心中的地理工具：給每個腳本用的距離和區域計算，在每個平台上都完全相同。

    自訂劇本

    • 執行環境：劇本在場地控制器上執行，告訴內建任務目標套件的盒子要扮演什麼（一個要佔領的點、一組密碼、要掃描的標籤或卡片、一個炸彈點）；盒子回報，劇本計分。
    • 編譯器：一個包含七種任務目標類型的 YAML 劇本，有相依關係、揭露和時間區間，檢查時會標出每個問題的位置並加以說明，再從命令列編譯。
    • 在 GM 控制台中：編輯器會在主辦輸入時列出每個問題，並安裝劇本；盒子加入時會拿到劇本的名稱。
    • 在 App 中：玩家看到給自己的任務目標，附名稱和各自的進度，隱藏的目標要等揭露後才看得到；每個小隊可以有自己的任務鏈，一次只有一個任務目標，完成後才揭露下一個，可以告訴整個小隊或只告訴小隊長。

    ATAK 與場地地圖

    • ATAK 資料：盒子和據點透過場地 Wi-Fi 顯示在 ATAK 地圖上，用佔領者的顏色標示，只要給場地圖片的兩個角落標上地圖位置就能定位。
    • GM 可以在場地平面圖上標出安全區、各隊的復活點和 HQ、停車場、急救站和任務目標，以圖釘、圓圈或區域呈現，每一個都可以設定給所有人、給某一隊或只給主辦看，顯示在控制台和 ATAK 上。
    • 場地可以從地圖載入：GM 可以從自己所在的位置或用地點名稱找到場地，在 OpenStreetMap 上描出場地的外框，瀏覽器就用 OpenStreetMap 的資料畫出場地圖片，疊在該國的開放空照影像上（葡萄牙本土、西班牙、法國含海外領土、荷蘭、比利時、盧森堡、瑞士、列支敦斯登、德國十一個邦、波蘭與捷克）。外框就是場地邊界，外面的區域會變暗。
    • 玩家離開邊界時，手機會用自己的 GPS 以橫幅和震動提醒，不會傳送任何資料。
    • 玩家位置絕不會給所有人看，只有在場地開啟時才會傳給工作人員的裝置。不在場地的工作人員可以透過場地伺服器拿到同樣的資料，連線經過加密，每台裝置都有一張由場地發出、可以立即撤銷的憑證；位置只會給 GM 或裁判。
    • 控制台中的多樓層場地：每個樓層一張平面圖，每個盒子放在自己的樓層。
    • 還沒用真正的 ATAK 手機試過，也還沒在真正的場地試過。
