# GM console

The organisers' web app for running a game from a phone, a tablet or a laptop. The field controller serves it; nothing is installed or built (ADR-P2-10: Preact and HTM as plain ES modules, no build step). It talks only to the controller's REST API v1 and its WebSocket stream ([controller/README.md](../README.md#rest-api-v1)).

Status: phase 2, plan phase E. Tested in headless Chromium against the real controller (with the C host modem as its radio, so box traffic arrives as encrypted packets); not yet used at a real field with real boxes (plan phase F).

## Opening it

Start the controller (see [controller/README.md](../README.md#running-it)) and open `http://<controller>:8080/` (it redirects to `/console/`). It asks for an access code:

- the **GM token** can do everything: create and run games, adjust scores, send messages, make join cards;
- the **read token** sees everything live but changes nothing (the GM controls are hidden and the API refuses them anyway).

`python3 -m atalaia_controller tokens` prints both. The code is kept in the browser (localStorage) until you sign out.

The code can also come in the address's fragment, as for the scoreboard: `http://<controller>:8080/console/#token=<token>` (`&lang=en` for English). The console takes it out of the address at once (it stays in neither the address bar nor the history; a fragment is never sent to the controller, so it is in no server log) and keeps it as a typed code once the controller accepts it. The app opens the console of a phone controller this way (decision PE24-71).

### On a phone controller

The Android app can be the field controller (decision PE24, slice S6) and serves this same console, but not every part of it yet. `GET /api/v1/whoami` lists the areas a controller serves (`features`, decision PE24-70); the console hides the tabs, panels and requests of the others, and the *Controlador / Controller* tab names them. Today a phone serves check-in, joining boxes, the boxes' language and players' positions; not the *Campo / Field*, *Adotar / Adopt*, *Predefinições / Presets* and *Cenários / Scenarios* tabs, the radio channel, the field's branding and team crests, saved teams, inviting boxes, firmware updates, modes sent to boxes, standby controllers, ATAK or the site's schedule. A controller that gives no list (an older one) serves everything. In the app's own web view, *Print the poster* and *Export CSV* need a computer's browser (the web view neither prints nor saves files); a short note says so there.

On a phone, "Add to home screen" installs it as an app (PWA, display standalone). A service worker keeps the console's own files, so it opens without a connection to the controller; live data needs the connection, and a banner shows while it reconnects (1 s, doubling to 15 s). A connection that goes silent without closing (a phone that slept, a dropped Wi-Fi) is noticed too: the console pings every 8 s, replaces a stream that has said nothing for 20 s and, as a safety net, asks the controller every 10 s which game is live, so a game made or started from another session (the API, another console) always shows (decision CL-2). API answers are never cached.

## Languages

European Portuguese by default, English, German and Traditional Chinese as written in Taiwan (`zh-tw`; both drafted by an AI model, to be reviewed: [docs/translations/](../../docs/translations/README.md)); the choice is remembered. The texts are in [`src/i18n/pt.json`](src/i18n/pt.json), [`src/i18n/en.json`](src/i18n/en.json), [`src/i18n/de.json`](src/i18n/de.json) and [`src/i18n/zh-tw.json`](src/i18n/zh-tw.json), with the project page's terms (caixa / box, equipa / team, controlador de campo / field controller, organização). Portuguese and English must have the same keys (checked by `controller/tests/test_console.py`); German and Chinese may lack a newer key, which then shows in English (`tools/i18n_check.py` lists them). Numbers take a decimal comma in Portuguese and German and a point in English and Chinese (`decimal()` in `ui.js`). The pages use the system's fonts; for Chinese (`<html lang="zh-Hant-TW">`) the stylesheets name Taiwan's Han fonts (PingFang TC, Noto Sans TC, Microsoft JhengHei) after the system font, so Han text never falls back to a Simplified or Japanese face. Blockly's own menus in the scenario blocks are Portuguese for Portuguese and English otherwise (only those two are vendored here). The printed check-in poster stays Portuguese and English. To add a language, copy `en.json`, translate it and add its code to `LANGS` and `HTML_LANG` in [`src/ui.js`](src/ui.js) and to `sw.js`.

## Branding

With a field's branding set, the console's header shows the field's logo and name on its accent colour (the login page too, before any token), the scores show each team's crest and display name, and the game card lists the teams as *name (colour)*. Without branding it looks as before.

## The check-in poster

[`src/poster.html`](src/poster.html) is the A4 page the field prints once for its check-in area: the field's name, a large QR code with the `atalaia:checkin:` text (error correction M; it holds no secret), the three steps in European Portuguese and English, and the short form of the field CA's fingerprint, which staff can compare with the console's. A field with a logo gets it above its name, apart from the QR code. It opens from the *Check-in* tab with the GM token the console keeps; the browser's *Print* prints the poster without the tools above it. If the field's Wi-Fi has a password, type it there to draw a standard Wi-Fi QR code beside the poster's: the password is used only to draw it, cleared from the form at once, and never stored or sent.

## The scoreboard

[`src/scoreboard.html`](src/scoreboard.html) is a read-only page for a TV or a laptop at the safe zone: the game's name, state and clock (time left when the game has a duration) and each team's score in large type, live over the WebSocket. With the field's branding: its logo and name above the game, its wallpaper behind a veil, and each team's crest and display name. Open

```
http://<controller>:8080/scoreboard#token=<read token>          (Portuguese)
http://<controller>:8080/scoreboard#token=<read token>&lang=en  (English)
```

The token is in the fragment, so it is not sent in the request or kept in server logs. **Share with players** (decision PD13): the Game tab's *Share the scoreboard with players* (`components/scoreboard-share.js`) shows this address, with the read code, as a QR code, which the app's *Player > Follow a game without checking in* scans; the GM asks to see it (it is a secret that only reads) and it is not kept on the page. For a scoreboard of your own over MQTT, see [examples/scoreboard/](../../examples/scoreboard/).


Security: the controller serves `/console/` with a Content-Security-Policy that allows only its own scripts, styles and API (`default-src 'self'`, no inline scripts or styles, images also from `blob:` and `data:`); two exceptions: the two stylesheets Blockly writes for the scenario blocks, allowed by their SHA-256 only ([`src/lib/README.md`](src/lib/README.md), decision P5F-2); and `field-map.html`, whose policy adds OpenStreetMap's tiles as images (`https://tile.openstreetmap.org`) the open orthophotos' services both as images (the *Ortofoto* layer's tiles) and as connections (the drawn image's one picture): every WMS of `components/ortho-sources.js` (the DGT's, IGN España's, IGN France's and PDOK's, `https://ortos.dgterritorio.gov.pt`, `https://www.ign.es`, `https://data.geopf.fr`, `https://service.pdok.nl`, MF-54, MF-71; and since MF-73 Belgium's regions', Luxembourg's, swisstopo's, eleven German Länder's, Poland's and Czechia's, `api.py FIELD_MAP_ORTHOPHOTOS`), and three WMS-less tile hosts as images only (`https://wmts1.geoportail.lu`, `https://wmts.geo.admin.ch`, `https://www.wmts.nrw.de`; MF-79), and the Overpass API with one other public instance and OpenStreetMap's Nominatim place search as connections (`https://overpass-api.de`, `https://overpass.private.coffee`, `https://nominatim.openstreetmap.org`), with scripts still same-origin only (decisions MF-27, MF-45, MF-51), and is the only page that may ask for the device's location (`Permissions-Policy: geolocation=(self)`, every other page `geolocation=()`: MF-43); `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. The pages therefore set every style through the DOM, never in markup. The join answers carry the game key; the API sends them with `Cache-Control: no-store`, and the console shows a warning next to them.

Run the browser tests with Docker from any shell:

```sh
python tools/docker_console.py              # builds tools/dev/console/Dockerfile on first use
python tools/docker_console.py -k scoreboard
```

CI's `console` job runs the same script (`controller/console/tests/run.sh`) in the same image. With `ATALAIA_REQUIRE_BROWSER=1`, as there, a missing Playwright, Chromium or `zbarimg` is an error, never a skip.

Not covered yet: real phones and tablets (only Chromium's phone-sized viewport), installing the PWA, writing an actual NFC card from the console (it shows the bytes; card writing needs a writer app or the box's reader, see protocol/join.md), and use at a real field (plan phase F).
