# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- Two radio diagrams in README.md and the project page ("How the radio works"): how LoRa works (chirps below the noise, spreading factor, range in the open and indoors, relaying with the hop limit, the EU868 rules) and which Skirmesh-RF layers each device runs, built and planned. `tools/build_site.py` builds them from `site/src/diagrams/*.svg` into `site/img/diagrams/` in each language, in a wide and a narrow layout, wraps their text and fails `--check` when a translation does not fit (measured with the widest common fallback font)
- Phase 2 mode pack: Hold-All Domination (`modes/holdall`, the controller's `field.lua` scores a team only while it holds every box), Last Stand (`modes/laststand`, a countdown to defeat while the defenders hold their last zone; the attackers win), per-team keypad codes on Bomb (`team_codes`), and the Codes modifier (`modes/codes`: keypad codes for points, hints and unlocks, reported to the GM with the holding team). New events 28–32 (`holdall.*`, `laststand.*`, ids from ADR-P3-8) and data fields `duration_s` (28) and `holder` (31) (phase-2-field-network, mode pack)
- Modifiers (`kind: modifier`) run alongside a main mode on the same box; a game names them as `main+modifier`, and the simulator, the controller and the Field Box compose the scripts the same way (phase-2-field-network, mode pack)
- Translated mode names and parameter labels (`i18n` in `mode.yaml`, European Portuguese for every built-in mode), shown by the GM console; modifier choice in the console's game and preset forms (phase-2-field-network, mode pack)
- The simulator runs a mode's `field.lua` as the controller does (`keys` test step, `serve --modifier`); the controller keeps `field.lua` points across restarts, restarts the script after a restart or takeover, and ends the game on a script's `game.win()` (phase-2-field-network, mode pack)
- Field Box: `code_entry` screen; all five modes built in as presets (a box adds missing built-in modes at boot and refreshes their scripts); joins with modifiers; Wokwi Codes scenario (phase-2-field-network, mode pack)
- Project page and README gallery: the game picker now lists all five modes, and the Codes modifier's code-entry screen is shown (phase-2-field-network, mode pack)
- Phase 3 (Android and players) design updated for the phase 2 handoff: I/O pod framing adopts USB modem sync+CRC-16; chrono readings signed by Ed25519 per marshal; Hold-All Domination and Last Stand moved to the phase 2 mode pack (event ids 28-32); join payload uses CA fingerprint + Wi-Fi fetch instead of the full certificate; single shared game channel (C5) propagated to pod CONFIGURE; Dart codecs must match schema-exact payloads (phase-3-android-players, commit 3f5ee7a)
- Phase 4 (site server) design updated for the phase 2 and 3 handoffs: custom-scenario compiler becomes a shared library at `controller/atalaia_controller/scenarios/`; events table unique key adds game time and event type; sync auth is asymmetric (API key controller→server, bearer token server→controller); GPS positions come from phones and pods, not the Field Box (E21); join is by QR, not BLE (phase-4-site-server, commit 9ffda1f)
- Screenshot gallery in README.md and the project page: seven captures of the real Field Box firmware (ESP32, LVGL 9.2, 320×240 TFT) running in the Wokwi emulator, walking through a Bomb game and a field join (bomb-1-pin through bomb-6-defused, join-joined)
- Field Box build manual (`hardware/field-box/BUILD.md`): parts and sourcing, enclosure, board revision and antennas, 1S power path with fuse, reverse-polarity diode and 5 V boost, step-by-step wiring with checks, first flash from Windows, troubleshooting; untested until the first build. Wiring diagrams generated with WireViz from `hardware/field-box/wiring/*.yml`, with GPIO numbers taken from Kconfig (`python tools/docker_hw.py render`), checked by `tools/check_wiring.py` in `check.sh` and CI (phase-1-single-box)
- Join payload (`protocol/join.md`, RFC 0001 Amendment 2): version byte, CBOR body, HMAC-SHA256 tag with a per-field join key; NFC (NDEF MIME record) and text/QR (`atalaia:join:` + base64url) forms; C codec with its own SHA-256/HMAC (`core/src/join.c`, RFC 4231 known answers) and Python codec (`simulator/atalaia_sim/join.py`), both checked against `protocol/vectors/join.json` (4 valid, 34 invalid) (phase-2-field-network, Phase E)
- Controller join flow: `POST /api/v1/join` and `POST /api/v1/nodes/{id}/join` make a payload for a box or a standby controller (text, QR-ready, NFC card bytes; GM token, never cached); `POST /api/v1/controller/join` makes a second controller stand by for a game, follow its TIME beacons and take over when promoted; `python -m atalaia_controller join-key` and `[join] key`; store schema 2 (per-game radio identity, field image, node positions) (phase-2-field-network, Phase E)
- GM console (`controller/console/src/`, Preact + HTM PWA, no build step, served at `/console/`): game control, preset builder from the modes' parameter schemas, live feed with alerts, node list, live scores, field view on an uploaded image, join panel with QR codes, controller status and promote; European Portuguese (default) and English; strict CSP; offline shell through a service worker (phase-2-field-network, Phase E)
- Scoreboards: a read-only page (`/scoreboard`, live over the WebSocket with the read token) and `examples/scoreboard/scoreboard.py`, an MQTT subscriber (phase-2-field-network, Phase E)
- Field Box on the radio (decision D18): `main/radio/field_link.c` sends the node's events (ACK, retry in new packets, flash-log replay after a reboot), HELLO and STATE, follows TIME (time sync with step and hold, leader by term, missed CMDs recovered from TIME), handles CMD and ACK, and relays authenticated packets once; `main/box_game.c` joins games (NFC card or `@join` on the serial console), keeps the join in NVS, runs the mode with the join's node id, seed, teams and parameters, ends and forgets the key, and rejoins after a reboot; PN532 NTAG user-memory reads for join cards; an optional field join key on the setup portal (phase-2-field-network, Phase E)
- Host box (`firmware/esp32/test/box_host`): the box's game and radio code on Linux with mbedtls, for end-to-end tests with the controller and the host modem over a shared UDP air (join, play, battery pull, end, relay through another box) (phase-2-field-network, Phase E)
- Tests: core join vectors and HMAC; 9 controller join and standby tests (two C modems on one air), 3 end-to-end field tests, console and scoreboard tests; Playwright browser tests in Docker (`python tools/docker_console.py`, CI job `console`); firmware host tests for the field link, the box game and the serial console; a Wokwi join scenario (phase-2-field-network, Phase E)
- Field controller (`controller/atalaia_controller`, Python, AGPL): games from mode packages and presets with start, pause, resume, end and automatic end at the time limit; the REST API v1 (the 15 endpoints of spec section 11 plus game list and detail, controller status, manual promote and `/healthz`) with read and GM tokens; the `WS /api/v1/stream` live feed; MQTT topics of spec section 11 through Mosquitto (retained score and node topics, GM commands on `cmd/`); SQLite store whose event log ignores replays and flood copies; `field.lua` run in the C core with `field.*` answered by the controller; recovery after a restart when `persist_game_key` is on (phase-2-field-network, Phase D)
- USB radio modem link: framing with a sync byte and CRC-16 (`protocol/usb-modem.md`), a ping every 5 s, reconnect after 3 missed pings, `radio.down`/`radio.up` alerts, the game configuration sent again after every reconnect (phase-2-field-network, Phase D)
- USB radio modem firmware: `sdkconfig.modem` / `python tools/docker_fw.py modem` builds `main/modem/` (USB-Serial-JTAG or UART0 link, AES-CCM, dedupe on source/epoch/seq, a 16-epoch receive window, nonce-reuse guard, task watchdog); the modem logic is plain C, unit-tested on the host and built into a Linux host modem the controller's tests talk to (phase-2-field-network, Phase D)
- Shared CLAIM election (`simulator/atalaia_sim/election.py`): priority score, missed-beacon detection, candidacy, step-down, manual promote; the simulator's `FieldController` now sends through a pluggable transport, ACKs per box and epoch, decodes events and drops replays, and is the radio side of the real controller (phase-2-field-network, Phase D)
- ctypes `field_ops` in the simulator's core bindings; CI jobs `controller` and `esp32-modem-build`; the dev image gains the controller's packages and Mosquitto (phase-2-field-network, Phase D)
- Core 0.2.0: `state.field{}` read-write/read-only field-level state, `field.nodes`, `field.owner`, `field.send`, `field.score`, `field.common_owner` script API functions (phase-2-field-network, Phase C)
- Radio HAL: SX1262 LoRa driver on SPI3_HOST (GPIO 8-14), EU868 SF7/BW125, single shared game channel (default 869.525 MHz, g2 sub-band, 10% duty cycle, 500 mW ERP) per RFC 0001 Amendment 1; FEM gain accounting via `radio_power.h`, duty-cycle tracking, DIO1 ISR, stub for Linux tests (phase-2-field-network, Phase C)
- Radio task: FreeRTOS core 0 priority 3, TX/RX queues with 8-slot depth (phase-2-field-network, Phase C)
- Flash event log: append-only on LittleFS, immediate flush for normal/critical events, telemetry cache with explicit flush, compaction after ACK (phase-2-field-network, Phase C)
- Time sync: slew adjustment (max 5%/tick, step above 500 ms offset), EMA-smoothed offset from TIME beacons (phase-2-field-network, Phase C)
- Radio protocol: Skirmesh-RF packet encode/decode with epoch persistence via NVS, per-source epoch trial on receive (tries stored epoch then epoch+1, never lower), `tx_blocked` on NVS failure or epoch exhaustion, nonce counter = (epoch << 16) | seq (phase-2-field-network, Phase C)
- NVS key storage: game key and epoch in "radio" NVS namespace, function-pointer abstraction for testability (`atalaia_radio_nvs_ops_t`), ESP-IDF backend with optional eFuse HMAC encryption (phase-2-field-network, Phase C)
- Partition table grown: OTA slots 1.5 MB to 2 MB, `nvs_keys` partition added for encrypted NVS (phase-2-field-network, Phase C)
- EU868 TX power calculation: centi-dBm integer arithmetic accounting for FEM gain and antenna gain, clamped to SX1262 range [-9, +22] dBm (phase-2-field-network, Phase C)
- Firmware test suite: 10 radio protocol tests (boot epoch, NVS failure, seq wrap, epoch exhaustion, receiver epoch trial with known/rebooted/lower/unknown sources), 6 TX power calculation tests (phase-2-field-network, Phase C)

### Changed
- Field Box preset scripts may be up to 16 KB (was 8 KB) (phase-2-field-network, mode pack)
- `code.used` carries `amount` and `holder`; `bomb.armed` and `bomb.defused` carry `reason` (phase-2-field-network, mode pack)
- In the simulator log, events at the same game time keep the order they happened in (phase-2-field-network, mode pack)

### Fixed
- Project page: the English LoRa glossary entry wrote `class=”nowrap”` with curly quotes, so its range figure was not kept on one line (no other curly quotes inside HTML tags in either language)
- `hardware/field-box/README.md`: the BoM had a 2S pack on the board's single-cell battery socket (it would destroy the board); Vext and the board's ADC were described as used by the firmware; button 2 was on GPIO 5, the V4.3 front-end module's line (phase-1-single-box)
- Heltec V4 radio front end: the FEM's power (GPIO 7, VFEM_Ctrl) was held low, which would have left the front-end module unpowered and the radio nearly deaf on real boards; it is now powered (LDO, then the revision's mode pin, then the chip enable) once the SX1262 answers, for the V4.3 (KCT8103L, GPIO 5 low = LNA) or the V4.2 (GC1109, GPIO 46 high = PA) chosen in Kconfig. Button 2 moved from GPIO 5 (the V4.3's FEM control) to GPIO 39; Vext (GPIO 36, active low) is switched on at boot; GPS is not supported in the Field Box pin map (phase-2-field-network, Phase E)
- Field Box: console input (`@join`, `@joinkey`, serial keys) is read from the board's USB-C port (USB-Serial-JTAG) as well as UART0, since the Heltec V4 has no USB-UART bridge; the LED ring's brightness is applied (40% at boot, `ring:set_brightness(percent)`); `python tools/docker_fw.py build` no longer takes a stray `firmware/esp32/sdkconfig` (it could hold Wokwi pin settings) and `clean` removes it (phase-2-field-network, Phase E)
- ESP32 shell: the serial console code used `CONFIG_ATALAIA_SERIAL_KEYS` in a C expression, which does not compile when the option is off (the Field Box default); found by a clean build (phase-2-field-network, Phase E)
- The core's payload codec (`msg_codec.c`) did not follow the schema and RFC 0001: HELLO capabilities, STATE counters, CMD params and CLAIM acks had other CBOR types, required fields were dropped when zero, and nothing was checked on decode; its vector tests skipped every vector it could not read, as did the Python ones. Both codecs now agree on every shared vector, byte for byte, and reject the invalid ones (phase-2-field-network, Phase D)
- The simulator's ctypes structs lacked `field_state` and `field_ops`, so the core read past the end of the Python config; the simulator's CBOR codec could not encode the ACK bitmap (phase-2-field-network, Phase D)
- Radio HAL: a BUSY timeout or SPI error is now returned to the caller instead of ignored, so a missing SX1262 is reported as "not detected" and released; the debug-step logs are debug level (phase-2-field-network, Phase D)
- Firmware: the memory monitor task overflowed its stack and crash-looped the box; the HAL drivers were never initialised; LittleFS was never mounted; the battery gauge and NFC reader claimed two I2C drivers on the same pins; the display flush queued an SPI transaction from the stack; the Wi-Fi setup never initialised Wi-Fi. Missing parts are now logged and skipped at boot (phase-1-single-box)
- `hardware/field-box/README.md` pin table now matches the Kconfig defaults (PCF8574 keypad, I2S on GPIO 6/15/16, backlight on GPIO 47, display RST on GPIO 38) (phase-1-single-box)
