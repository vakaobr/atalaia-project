# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

### Added
- The controller sync (phase-4-site-server plan phase 13, ADR-P4-3 as amended; in software, tested against the real site server and PostgreSQL in Docker, not yet over a real 4G link): field controllers push their games to a site server, opening every connection themselves (decision P4R12). Site server: `POST /api/v1/sync/games`, `events`, `scores` and `nodes` and `WS /api/v1/sync/stream`, with a field API key (32 random bytes kept only as SHA-256, at most two live during a rotation, managed by the field's admin at `/api/v1/fields/{field}/sync-keys`, P4R13); a game is `(field, game_id, game_seed)` (P4R11), so a standby controller's pushes land in the same game and a reused 16-bit id is a new one; events unique on the controller's own key, so replays, duplicates and out-of-order batches change nothing; score counters per node (and per run of a controller's field script) merged by `GREATEST`, totals derived with every `score.delta`, so a GM's negative adjustment lowers them (P4R10); per-game roles (`user_game_roles`, `/api/v1/games/{game}/roles`) and a small games API (a field's games, a game with its totals, counters and nodes, its events); per-game roles in access, export and erasure, and games purged 24 months after they ended; migration `0004_sync`; sync counters in the metrics. Controller: `sync_client.py` (a thread that only reads the store, so a game never waits for the network; every 30 s in a game and 5 min between, doubling on failure up to 5 min, honouring `Retry-After`, woken by a game's start, pause and end; HTTPS against the system's CAs or `[sync] ca_file`, no redirects followed; its per-game cursor in `sync_state`, store schema 5), `[sync]` settings (off by default), `python3 -m atalaia_controller sync-key` (store a key, `--status`, `--clear`, `--resend`) and `sync` in `GET /api/v1/controller`; never sends positions, check-in names, tokens or keys. The wire format is `protocol/sync.md`, checked on both sides by `controller/atalaia_controller/sync_format.py` against the shared vectors `protocol/vectors/sync.json`. No new dependency on either side. Tests: `server/tests/test_sync.py`, `test_sync_stream.py`, `test_sync_e2e.py` (the real controller engine and client against the site server under uvicorn on the test PostgreSQL), `controller/tests/test_sync_client.py` (against a small site server in the test process, privacy checked field by field) and `test_sync_format.py`; decisions S13-1 to S13-12
- Site server personal data rights (`server/`, phase-4-site-server plan phase 12, ADR-P4-8; in software): `GET /api/v1/me/data` (everything held about the account: profile without credentials, roles per field, sessions with addresses and user agents, the person's audit entries and the ones others made about the account without who made them, consent records) and `GET /api/v1/me/export` (the same as a ZIP of JSON files with a README in English and Portuguese); rectification with `PATCH /api/v1/me` (username, email) and `POST /api/v1/me/password` (ends every other session), both behind the current password; erasure with `DELETE /api/v1/me` (the password, and a TOTP code for an account with TOTP) that anonymises the account as a `deleted-...` tombstone, deletes its roles, sessions and consents, keeps its audit entries without their addresses and logs the erasure with no account and no address, refusing the last server administrator; consent records with the privacy notice's version (`consents`, `ATALAIA_PRIVACY_NOTICE_VERSION`); the daily retention purge inside the server (`ATALAIA_PURGE_HOUR`, 03:00 UTC by default: sessions 30 days after they end, the audit log after 36 months) and `python -m atalaia_server purge [--dry-run]`; migration `0003_personal_data`; tests in `test_personal_data.py`; decisions S12-1 to S12-8
- Templates for field operators, to be reviewed by a lawyer before use (decision P4-6): the site server's privacy notice in Portuguese and English (`docs/templates/privacy-notice-pt.md`, `privacy-notice-en.md`) and a data processing agreement for a hosted server (`docs/templates/dpa-template.md`)
- Core: geo utilities for node and field scripts (ADR-P4-9, phase-4-site-server plan phase 3; in software): `geo.distance(lat1, lon1, lat2, lon2)` in metres (haversine on a 6,371 km sphere) and `geo.in_zone(lat, lon, zone)` for a circle (`lat`, `lon`, `radius_m`) or a polygon of 3 to 32 `{lat, lon}` points, a point on the edge counting as inside; wrong arguments are script errors (`core/include/atalaia/geo.h`, `core/src/geo.c`). The results are the same to the bit on every platform, so replays agree: only `+ - * /` and `sqrt`, its own sine, cosine and arc tangent instead of the C library's, compiled with `-ffp-contract=off` (decisions M3-1 to M3-3)
- Shared vectors `protocol/vectors/geo.json` (generated into `core/tests/geo_vectors.h` by `tools/protogen.py`): known answers from Rosetta Code (haversine, ray casting) and GeographicLib (a WGS 84 geodesic) with their tolerances, arcs along a meridian and the equator, antipodes, edge cases and argument errors, and every distance's exact bits; run by `core/tests/test_geo.c` and `simulator/tests/test_geo.py` (from Lua through the shared library). The same bits were checked on arm64 and armv7 (gcc and clang) and on the ESP32 and ESP32-S3 in QEMU; the Field Box image grows by 5.4 KB
- Site server accounts, sessions and roles (`server/`, phase-4-site-server plan phase 11; in software): registration with consent, the NIST SP 800-63B password policy (10 characters or more, no character-class rules, not the username, not one of the UK NCSC's 100,000 most breached passwords) and Argon2id hashes with ADR-P4-2's parameters (re-hashed at login when they change); login, then a TOTP step (RFC 6238, 6 digits, one step of drift, each code accepted once, seeds Fernet-encrypted at rest) for accounts that have it; 15-minute JWT access tokens whose session and roles are re-read from the database on every request, so a logout or a removed role counts at once; refresh tokens in an HttpOnly, Secure, SameSite=Strict cookie limited to the refresh path, stored only as SHA-256, rotated on every use, a replayed one ending the whole session; TOTP enrolment, confirmation and removal; lockouts (5 failed logins per address, 5 wrong codes per account, 15 minutes each), 10 registrations an hour and 100 requests a minute per address; fields and per-field roles (player, squad_leader, vip, marshal, gm, spectator, admin) with TOTP required, and a TOTP login, for admin, gm and marshal; the audit log for every login, failure, lockout, replay and role change; `python -m atalaia_server create-admin`; `GET /api/v1/metrics` for server administrators (or the optional metrics token); migration `0002_accounts`; new hash-pinned dependencies argon2-cffi 25.1.0, PyJWT 2.15.1 and pyotp 2.10.0; tests with the RFC 6238 and RFC 4226 test vectors; decisions S11-1 to S11-15
- The site server's skeleton (`server/`, phase-4-site-server plan phase 10; in software, no accounts yet): a FastAPI app factory (`atalaia_server.app:create_app`), settings from `ATALAIA_*` variables (a wrong value stops the start; the database password never logged), SQLAlchemy 2's async engine on asyncpg against PostgreSQL 16, the base models with UUIDv7 keys (RFC 9562, checked against its example), Alembic with the first reversible migration `0001_base` (fields, users, roles seeded with ADR-P4-1's seven, per-field roles, sessions, the audit log), `GET /api/v1/health` (200 healthy, or 503 when the database does not answer), `GET /api/v1/metrics` behind a bearer token until admin accounts exist, and security headers on every response (HSTS, `nosniff`, `X-Frame-Options`, a content security policy, the referrer policy); decisions S10-1 to S10-12
